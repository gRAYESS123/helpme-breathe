The statement

I attest that the Help Me Breathe breathing timer, the embedded widget and the co-branded client session links collect no personal data about the people who use them, and transmit none to me or to anyone else. There is no account, no client record and no database in which such data could be held.

What the widget does

It draws a circle that grows and shrinks on a fixed schedule, counts the phases of a breathing pattern, and optionally plays a tone and vibrates the device at each change. That is the whole product. Everything it does happens inside the browser of the person using it:

  • The breathing pattern is read from a JavaScript file that ships with the page. No pattern is fetched from a server during a session.
  • Cue tones are generated in the browser with the Web Audio API. No audio file is downloaded and no microphone is opened.
  • Vibration, where the device supports it, uses the browser's Vibration API.
  • Settings — chosen technique, session length, sound on or off, vibration on or off — are written to that browser's own local storage under the prefix hmb.. So is a local history of completed sessions, on the main site.
  • Nothing in that local storage is read by a server, sent in a request, or recoverable by me. Clearing the browser's site data deletes all of it.

What the widget does not do

  • It does not ask for a name, an email address, a date of birth, a health condition or any other detail about the person using it.
  • It does not create an account, a profile or a client identifier, because there is no account system anywhere in the product.
  • It does not record what was practised, for how long, or when, anywhere other than that person's own browser.
  • It sets no cookies of its own.
  • Inside the embedded widget there are zero third-party requests of any kind: no web fonts, no analytics, no advertising, no tag manager, no tracking pixel, no error-reporting service. The frame loads its own HTML, CSS and one script from helpmebreath.com, and nothing from anywhere else.
  • Inside a client session link there is no analytics, no advertising, no tag manager, no tracking pixel and no error-reporting service. It does make one third-party request, and it is named in the next section rather than left out of this list.
  • It does not use a camera, a microphone, location, a heart-rate sensor or any other device sensor.
  • No data from it is sold, shared for advertising, or used to train any model.

Where data does move, stated plainly

An attestation is only worth reading if it also lists the exceptions. There are four, and none of them concerns what a person practised.

  • Serving the page. The page has to be fetched over the internet, so the hosting provider's servers see the requesting IP address, the browser's user agent string, the URL and the time, exactly as they would for any website. That is ordinary web serving. It is not analytics, and I do not build profiles from it.
  • One web font on a client session link. The page at /s/ asks Google Fonts for the Quicksand typeface, so that the link looks like the rest of the site. Google's font servers therefore see the reader's IP address and user agent, as they would for any site using a hosted font. No identifier is sent with it, nothing about the session is included, and the page works normally if the request is blocked. The embedded widget does not do this: it makes no third-party request at all. If a hosted font is a problem for your setting, use the embedded widget rather than a session link.
  • Analytics on the main site only. The public pages of helpmebreath.com run Google Analytics 4. Google Consent Mode defaults are set to denied, so nothing is measured until a visitor chooses to accept in the cookie banner. Analytics never runs inside the embedded widget, and never inside a client session link.
  • The practitioner's own licence email. If you hold a Practitioner or Studio licence, the merchant of record holds the email address and billing details you gave them at checkout, and I hold your email address and our correspondence. That is data about you, the practitioner — not about anyone you work with.

A co-branded client session link carries your name, your chosen pattern, your session length and your message encoded inside the link itself. That is why no server needs to remember it. There is no record on my side of which link was made, who received it, or whether it was opened.

What this attestation is, and is not

This is a self-attestation. It is my own statement about my own product, given in good faith and accurate on the date above. It is not a third-party audit, not a certification, and not a substitute for one. Nobody independent has verified it.

What you can do instead of taking it on trust: open your browser's network panel on any page of the site, or on a page where the widget is embedded, and watch what is requested. Inside the widget frame you will see the page and its own script, and nothing else. That check takes about a minute and is more convincing than this paragraph.

If this ever stops being true — if a future version of the widget needs to send something — this page gets a new version number and a new date, and licence holders are emailed before the change ships.
