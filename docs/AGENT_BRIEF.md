Revenue streams in priority order: (1) the subscription — the $2k/month lever, (2) AdSense on **content pages only**, (3) affiliates (Headspace, moonbird direct — never Calm, never Amazon). There is no tips or donations stream.

### Serverless functions (`api/`)
Vercel Node runtime with **Web-standard handlers** (`export async function POST(request) { return Response.json(...) }`), WebCrypto (`crypto.subtle`) for HMAC and `fetch` for everything else, so the code is portable to Cloudflare Pages Functions with a two-line adapter and needs **zero npm runtime dependencies** — including on the server, which is why Supabase is reached over PostgREST and the JWKS by hand rather than with supabase-js. Shared modules live under `api/_lib/` because Vercel does not turn underscore-prefixed files into functions.

Env vars: `KNOWN_VARS` in `api/_lib/env.js` is the single list, `.env.example` explains each one, and `GET /api/health` says which are unset on a deployment. Sign-in is a magic link, a 6-digit code or Google, carrying `?next=` and `?intent=subscribe:<plan>`; `/auth/callback` completes it and resumes the intent in place. `GET /api/me` is the only endpoint the signed-in front end calls, and the browser never talks to PostgREST.
- **The timer gate**: `js/app.js`'s `start()` calls `requireTimer({technique})` once. False means the engine enters preview mode and dispatches `hmb:preview` with `{ reason: 'signed_out' | 'no_subscription' }`; `js/pro/preview.js` answers with one demonstration cycle and one card, and stamps `body.timer-preview` so `js/ads.js` stands down. Pages with `<body data-open-timer="true">` — the two crisis pages, and nowhere else — always pass. `tools/site-check.mjs` enforces that allowlist.
- **Checkout**: `js/checkout.js` exports `subscribe(plan)` (`plan` ∈ `monthly|yearly`), with `checkout(sku)` kept as an alias. Pages use `data-action="checkout" data-plan="yearly"`. `js/config.js` exports `CHECKOUT` as `{ clientToken, sandbox, previewPriceIds }` — no `mode`, no `urls`, no price id used to open anything. A click POSTs to `/api/trial/eligibility`; the **server** decides trial-or-not, picks the price and creates the transaction, and the overlay opens with that transaction id. With no `clientToken` configured the button renders a calm "Checkout is not open yet" card — there is no waitlist.
- **The entitlement token** (v3): `base64url(payloadJSON) + "." + base64url(HMAC-SHA256)`; payload `{ v:3, typ:'ent', sub, tier, st, plan, pe, iat, exp, kid }` where `sub` is the Supabase user id. `exp = min(iat + 14 days, access_until + 24h)`; those 14 days **are** the offline grace and there is none past `exp`. Minted by `GET /api/me`, stored at `localStorage['hmb.ent']` and in the `__Host-hmb_ent` cookie.
- **Email capture** posts `{ email, technique, source, consent: true }` to `/api/subscribe` and expects `{ ok: true, message }` or `{ ok: false, error }` (API agent).
- **Ad slots**: `<aside class="ad-slot" data-ad-slot="in-content-1" role="complementary" aria-label="Advertisement"></aside>` (Core styles reserve height; `js/ads.js` fills). Never `aria-hidden="true"` — AdSense puts focusable links inside it. Allowed only on content/comparison pages, never on the pages listed in rule 6.
- **OG images**: reference `/images/og/<slug>.jpg`; the Render agent generates one per slug in `tools/og-manifest.json`.
